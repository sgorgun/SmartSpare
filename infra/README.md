# Infrastructure

Azure resources of SmartSpare in Bicep (ADR 0009 amended, ADRs 0015–0020, STAGE_4_PLAN 8.5–8.8). Nothing here is
applied before the first deployment in stage 10 (#85). Until then `infra.yml` only builds and lints the templates, and
runs what-if when Azure sign-in is configured.

| File | Contents |
|---|---|
| `main.bicep` | Subscription scope: the resource group `rg-smartspare-prod` and the three modules |
| `modules/platform.bicep` | One managed identity per app and job; ACR Basic; Key Vault (RBAC) with the gateway's Data Protection key; storage for the gateway's key ring; PostgreSQL 17 B1ms; the Container Apps environment (Consumption, no Log Analytics) |
| `modules/apps.bicep` | The gateway (external ingress) and six services (internal ingress), 0.25 vCPU / 0.5 GiB, 0–1 replicas; the KEDA queue rule for consumers; the `migrations` job; the `broker-metrics` job (off until #85) |
| `modules/budget.bicep` | The €35 monthly budget with alerts at 50, 80 and 100 % and at a 100 % forecast |
| `main.prod.bicepparam` | Production parameters; the image tag, the admin password and the budget address come from the environment |
| `observability/` | Dashboards, alert rules and the local Grafana stack (its own README) |

## What the first deployment needs (stage 10)

**Created by hand:** the CloudAMQP instance (ADR 0017) and the Grafana Cloud stack (ADR 0018).

**Key Vault secrets**, read by the apps through their own identities:

| Secret | Value |
|---|---|
| `db-identity` … `db-reporting` | Connection string of each service's login (`smartspare_identity` …; Reporting uses `smartspare_reporting`) |
| `db-migrator` | Connection string of `smartspare_migrator` |
| `messaging`, `rabbitmq-management` | CloudAMQP's AMQPS URL and management URL with the vhost (KEDA http mode, BROKER.md) |
| `internal-token-signing-key`, `internal-token-jwks` | The gateway's ES256 key (PEM) and its public JWKS (ADR 0016) |
| `otlp-endpoint`, `otlp-headers` | Grafana Cloud's OTLP gateway and its `Authorization` header |

**GitHub repository settings:**
- variables `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID` (OIDC federated credential, no secret), `ACR_NAME`, `ACR_LOGIN_SERVER`, `RESOURCE_GROUP`, `GATEWAY_URL` and `BUDGET_EMAIL`;
- the secret `POSTGRES_ADMIN_PASSWORD`.

`DEPLOY_ON_PUSH=true` then turns on deployment on every push to `main`, and `DB_SCHEDULE_ENABLED=true` turns on the nightly database stop.

## Deploying

- `infra.yml`, manual, mode `deploy`: the templates.
- `deploy-migrations.yml`: the first `migrate`, which bootstraps the logins and runs every context.
- `deploy-<service>.yml`: build the image, migrate the module (`tools/run-migration-job.sh`, ADR 0020), roll out the revision, smoke-test through `/warmup`. Their path filters are generated by `tools/generate_deploy_workflows.py` and checked in CI.

Validate locally with `az bicep build --file infra/main.bicep` and `az bicep lint --file infra/main.bicep`.
